# VELO 0.5：应用内选目的地与自行车规划

新版首页改为起点、目的地、路线预览和底部固定的“开始骑行”。路线来自 BRouter 自行车服务，Google 地图应用和通知访问都不再参与导航。本版无需重新烧录已安装的 v0.4 ESP32 固件。

## 手机安装

关闭电脑原来的下载窗口，双击“开启手机下载.cmd”，手机与电脑连接同一个 Wi-Fi，然后下载并覆盖安装：

http://192.168.45.24:8765/VELO-PhoneBridge-v0.5.apk

覆盖安装保持同一签名，不需要卸载旧版本。手机可关闭以前授予 VELO 的通知访问；新版本清单中已移除通知监听服务。普通的骑行状态通知仍用于后台定位服务。

## 开始一条路线

1. 点“使用当前位置”，选择手机定位；也可以搜索起点，在室内先规划路线。
2. 点“搜索地点或输入坐标”，输入城市和地点名，在候选结果中确认目的地。
3. 如果系统地名搜索不可用，直接输入 `纬度,经度`，例如 `35.6812,139.7671`。不要颠倒顺序。
4. 点击“规划自行车路线”。完成后查看路线预览、距离和预计时间。
5. 点击底部“开始骑行”，授权精确定位、附近设备和普通通知权限，选择已配对的 VELO-ESP32。
6. 手机锁屏留在口袋，码表显示路线与下一指令。真实定位请在室外验证，TCL 后台省电限制仍需实测。

预览白点是起点，空心圆是终点，运行时红点是当前位置；保持北朝上。点击码表 BOOT/GPIO0 可切换路线页和码表页。

## 在家验证

右上角“设置” → “回放当前路线（模拟）”。模拟位置会沿已规划路线移动，不需要在家绕圈；屏幕标注 REPLAY。也可载入虚构路线进行回放。真实骑行前，在工具中切回真实 GPS 跟随；虚构路线不允许直接切为真实导航。

GPX 导入、回放、配对、权限和结束骑行统一放在“设置 / 骑行工具”中。

## 已验证与限制

- 已在 Android 14 模拟器跑通坐标选点、在线规划、路线预览、应用重启后恢复路线；地名搜索已返回候选地点。公开地点测试路线约 1.26 km、15 条路口提示。新增 29 项规划/坐标检查和原有 727 项几何/显示协议检查通过。
- 新 APK 已签名并验证；尚未在 TCL 手机上安装此版本。上一版固件已在 COM8 验证路线帧通信，新版本沿用同一协议。
- 规划使用 BRouter trekking 自行车配置，可能包含需推行的路段；服务结果需结合现场道路和自行车通行规定判断。GPS、路口匹配及复杂路线需实骑验证。
- 展示简单路线，没有附近道路底图。路线服务提供转向指令；GPX 仍从轨迹几何推导拐点。
- 环岛和特殊指令暂不展示出口编号，码表保留路线线条并显示无明确指令，不能猜测出口。
- 偏航目前提示偏离路线，需手动重新规划；尚未加入自动重算和蜂鸣器。
- 路线规划需要联网，下载完成后可离线跟随；保存的路线可在重启后恢复，骑行记录仍不持久化。
- 公共测试服务限制为起终点直线距离 80 km 内，响应至多 12000 点 / 4 MB。服务没有可用性保证，失败时保留原路线。仅手动请求规划，至少间隔 1.5 秒；设置中可更换兼容的 HTTPS BRouter 服务。
- 搜索由 Android 系统 Geocoder 提供，具体后端和可用性取决于手机系统。它不依赖 Google 地图应用，但不承诺完全不使用 Google 的系统服务。

## 数据与开源参考

规划会把起终点发送至所选路线服务；地点搜索使用手机系统地名服务。缓存保存在手机应用内部文件中，没有自动批量查询或输入联想请求。

- BRouter：https://github.com/abrensch/brouter （MIT；服务协议与转向编码参考，许可文本随包提供）
- BRouter-web：https://github.com/nrenner/brouter-web （MIT；参考起终点、路线预览和规划流程）
- Material Components：https://github.com/material-components/material-components-android （Apache-2.0；参考卡片、颜色与操作层级）
- OpenStreetMap 数据归属：https://www.openstreetmap.org/copyright

手机界面使用原生 Android 重新实现，没有复制上述项目的 UI 源码或图片，没有引入完整 Web 地图或 Material 组件库。
