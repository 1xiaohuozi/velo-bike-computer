# VELO App 改版设计方案

日期：2026-10-16。基线：Android 0.10.0。本文与交互原型是下一版的设计依据，不代表这些功能已经发布到 APK。

## 1. 产品定位与现状

定位：为自行车码表提供地图、目的地规划、个人地点管理和后台导航的手机应用。手机负责出发前的准备与骑行后的整理；骑行中主要看码表。

当前界面的问题来自结构：地图、起终点、日志、连接、规划、回放集中在一个滚动首页；多个功能藏在通用弹窗；地图还分小预览与独立大地图。用户必须了解内部实现，才能完成一次操作。

已核对代码：

- `MainActivity` 同时承担页面、搜索、数据写入、权限、规划和设备选择；状态靠定时轮询与多个布尔值组合。
- `MapPins` 已能保存、重命名和删除标签，但仅有 ID、名称、坐标；入口隐蔽，没有分类、备注、检索、备份与完整收藏管理。
- `RouteStore` 只保留最后一次在线规划或导入的路线，不是路线库。
- 当前“开始骑行”与蓝牙选择耦合。应允许没有码表时独立搜索、收藏、规划及手机导航。

目标是让用户完成：**找到地点 → 看清地点 → 收藏或规划 → 预览路线 → 开始骑行 → 结束并保存记录**。

## 2. 开源参考与采用范围

| 参考 | 借鉴内容 | 在 VELO 中的落点 |
|---|---|---|
| [Organic Maps](https://github.com/organicmaps/organicmaps) | 地图为主、地点操作、书签与轨迹入口 | 地图首页、统一地点详情、收藏与路线入口 |
| [OsmAnd 收藏设计](https://osmand.net/docs/user/personal/favorites/) | 分组、图标颜色、备注、排序、地图显隐、导入导出 | 完整收藏系统，首版只选日常骑行需要的功能 |
| [BRouter-web](https://github.com/nrenner/brouter-web) | 地图上编辑起终点及途经点 | 规划草稿与明确的路线预览 |
| [MapLibre](https://github.com/maplibre/maplibre-native) | 地图引擎与地图要素渲染 | 手机原生地图、统一手势与标记交互 |
| [Android 架构建议](https://developer.android.com/topic/architecture/recommendations) | 数据层、界面状态、ViewModel、单向数据流 | 消除页面互相改字段和隐式状态 |

本轮参考交互与组织方式，不复制其他项目品牌或整个应用内核。若后续复用源码，记录来源、固定版本、许可和第三方声明。BRouter-web 的 MIT 许可不等于所有地图项目均可按同样方式移植；具体子目录及依赖需要分别核对。

## 3. 四个一级入口

底部固定：**地图 / 收藏 / 路线 / 设备**。设置收进设备页右上角；调试、接口地址与日志归入高级设置。

### 地图

地图铺满可用区域，顶部固定一个搜索入口。右侧只放定位、图层、地图中心标点三个常用按钮。底部是一张可收起的操作面板：浏览、地点详情、路线预览分别呈现对应内容。

首页不再出现大标题、营销语、长说明和重复的“规划/开始”按钮。设备连接状态只占一个小入口；没有设备也能用地图。

### 收藏

完整的个人地点库：搜索、分组、列表与地图查看、排序、新建、编辑、导入和导出。家与常用地点可置顶。收藏名称与描述可同时检索；距离未知时显示“距离待定位”，不显示假数字。

### 路线

顶部“已保存 / 骑行记录”切换。保存的路线包括几何、起终点、途经点和规划参数；骑行记录包括实际轨迹与骑行摘要，两类数据不能混在一起。导入 GPX 位于这里，回放位于具体路线详情中。

### 设备

显示选中的 VELO-ESP32、连接状态、最后收到数据的时间、重连操作与导航提示设置。定位权限、蓝牙权限和连接失败分开解释；没有权限时直接给对应处理入口。

没有读取到真实电量、硬件版本或传感器数据时，不制造这些指标。

## 4. 核心操作

### 搜索与选中地点

1. 点首页搜索，进入搜索页；先展示收藏、最近地点和坐标入口。
2. 输入时本地收藏即时过滤；在线搜索遵循供应方限流，首版按提交查询，不对公共服务进行逐字轰炸。
3. 结果显示名称、完整地址、可用时的距离及来源；保留当地语言名称。搜索错误、零结果与离线是不同状态。
4. 点结果，回到地图并弹出地点详情。**选中结果不会立即开始导航**。
5. 地点详情的主要操作为“骑行去这里”，次要操作为“收藏”“设为起点”“途经这里”。

地图长按、点击 POI、收藏列表和搜索结果打开同一种地点详情，不再分别实现四套选择流程。十进制和度分秒坐标复用已验证的解析器。

Photon 等免费服务的覆盖不会因换界面就达到 Google 同等水平。应明确展示失败原因，并始终保留地图选点、坐标与离线收藏；不把缺少数据误报为“目的地未选中”。

### 收藏完整流程

任何地点详情都能收藏；地图中心标点和长按地图也能新建。保存时编辑名称、分组、备注、图标与颜色，坐标可检查或修改。

默认分组：常用、补水、休息、维修、风景、其他；支持自建分组。分组可以显示或隐藏于地图，删除分组默认将地点移到“其他”，不能悄悄删除组内地点。

列表支持按名称、最近修改、距离排序；远距离或密集地图使用聚合，不能铺满重叠图钉。近距离重复收藏应提示已有地点，允许保留不同用途，不直接覆盖。

删除提供撤销；误触不会立即永久丢失。名称和分类变更必须同步更新列表、地图和搜索结果。

首批提供 GeoJSON 地点导入导出，后续补充 GPX waypoint 导入；文件从 Android 系统文件选择器读取或保存。文件损坏时保留原数据，预览数量、重复项和冲突处理后再提交。KML/KMZ 作为后续兼容项，不在首版假装支持。

### 规划与路线库

选择“骑行去这里”后，默认起点为当前有效位置；位置尚未取得时显示明确的等待状态，并允许改选起点。支持交换起终点、添加/删除/排序途经点。

规划中保持地图和取消入口可用。只有与当前草稿版本完全一致的返回结果才能进入预览；旧请求晚返回必须丢弃。

预览显示路线、距离、可用的预计时间和真实返回的路面/高程信息。首版先做好一种经过验证的自行车规划，不显示三个实际相同的“推荐/最快/最短”假选项。

预览中可编辑地点、保存路线、开始导航。保存路线有名称和备注；再次打开可查看、改名、复制、分享或骑行。收藏改名不会破坏已保存路线的坐标快照。

增加途经点不能仅画直线连接：必须逐段请求实际骑行路线，拼接几何和转向里程。任意一段失败时标出失败段，禁止将残缺结果当完整路线开始。

### 骑行状态

进入骑行后保持地图为主，大号下一转向提示、剩余距离与到达时间。非必要入口收起。切到其他页或锁屏后，后台导航持续运行；回来能恢复当前骑行。

蓝牙断开时手机导航继续，设备状态提示并后台重连。GPS 不可信时暂停明确转向，显示“等待定位”，不能继续显示过时的指令。反向行驶提醒沿用已有持续位移确认逻辑。

暂停、继续、结束是不同操作。结束后选择保存或丢弃记录；异常退出后提示恢复，不能静默创建一场新骑行。模拟回放必须持续显示标识，不能写入真实骑行统计或触发走反报警。

## 5. 视觉与交互规范

- 主色为克制的深蓝，地图降低饱和度，导航路线保持清楚对比；橙色用于待确认，红色只用于错误或反向提醒。
- 采用统一的系统字体与线性图标；正文 16sp、辅助文字 13–14sp、页面标题约 24sp。重要点击目标至少 48dp。
- 统一 8dp 间距节奏，页面左右 16–20dp。地点操作使用底部面板，表单使用独立编辑页；不叠加多层通用弹窗。
- 每种状态只有一个主要操作，例如地点详情为“骑行去这里”，规划预览为“开始骑行”。
- 输入、地图浏览、选中地点、规划、预览、骑行之间保持返回路径；返回收藏列表保留搜索词和滚动位置。
- 首版完成明暗主题、键盘避让和大字体布局验证，不只验证一张固定尺寸截图。
- 设备小屏与手机使用相同的路线/位置/警告语义；手机负责完整个人地点管理，码表显示少量相关标点，后者另立兼容升级任务。

## 6. 工程结构

将现有手工编译脚本逐步迁入可复现的 Gradle Android 工程。新界面采用 Kotlin + Jetpack Compose；地图优先以 AndroidView 承载 MapLibre Native，先验证性能与现有手机兼容性，再决定是否引入额外 Compose 地图封装。

保留经过验证的 Java 几何、GPS 航向、反向判断和 H/B/T 码表协议，先通过适配层调用。地图渲染与业务层解耦；迁移期间可保留现有 WebView 地图作为过渡，不把一次引擎切换与所有业务改造绑在一起。

开始时用清晰的 package 分层即可，不为了形式拆大量 Gradle module：

```text
ui/map, ui/search, ui/place, ui/favorites, ui/routes, ui/ride, ui/device
data/local, data/search, data/routing, data/maps, data/device
navigation/geometry, navigation/matching, navigation/guidance
service/ride
```

界面由 ViewModel 暴露明确状态，通过 Repository 读写；数据库用 Room，设置用 DataStore。GPS、蓝牙和骑行生命周期由服务管理，切页面不重建导航线程。

持久化实体：

| 实体 | 关键内容 |
|---|---|
| Favorite | UUID、名称、地址、纬经度、分组、备注、图标、颜色、来源、创建/修改时间 |
| FavoriteGroup | UUID、名称、排序、地图显隐、默认样式 |
| RouteDraft | 草稿版本、起终点快照、途经点顺序、规划参数 |
| SavedRoute | UUID、名称、几何文件、转向、距离/时间、途经点快照、来源、修改时间 |
| RideSession | UUID、路线引用、开始/暂停/结束状态、实际轨迹、摘要、模拟标记 |
| RecentPlace | 地点快照、最后使用时间；可独立清空，不影响收藏 |

网络搜索、规划和地图缓存分别管理超时与重试。收藏离线读写；搜索请求有取消与序号，返回较早查询的结果不能覆盖较新输入。规划草稿和导航会话使用独立版本，修改目的地不会悄悄替换正在导航的路线。

## 7. 已有数据迁移

应用包名与签名保持可升级。首次迁移先备份旧数据，事务导入 `map_pins`、起终点、最近地点以及最后保存的路线。旧标签进入“未分类”组，保留原 UUID 和坐标；只缺名称时生成可见的待补名称，不静默丢弃。

以旧 ID 和迁移版本去重。只有事务成功才写迁移完成标记；失败允许重新尝试，不能删旧 SharedPreferences 和路线文件。升级后检查数量和坐标，提供导出备份入口。

## 8. 实施顺序与交付门槛

| 批次 | 交付 | 必须验收 |
|---|---|---|
| A：信息结构与个人地点 | 四入口、地图首页、统一地点详情、收藏 CRUD/分组/搜索/地图显隐/GeoJSON 备份、旧数据迁移 | 搜索/地图/收藏三种入口均可收藏及规划；重启不丢点；升级不丢旧标签 |
| B：规划与路线库 | 起终点/途经点、可靠的预览、保存多条路线、GPX 导入、分享与回放入口 | 选定目的地不丢失；多段规划完整；旧请求不覆盖新草稿；保存与导航路线一致 |
| C：骑行与设备 | 独立骑行页、后台状态恢复、蓝牙重连、结束保存记录、地图原生化收尾 | TCL 真机锁屏 30 分钟；断连重连；GPS 弱信号；走反与正常掉头；模拟不污染记录 |
| D：补全与迭代 | GPX waypoint 导入完善、收藏批量管理、更多搜索供应方、按实际需求做离线区域 | 格式与冲突清楚、导出后能重新导入；不将缓存宣称为完整离线地图 |

先交付 A 和 B 中的主要闭环，不先增加天气、排行榜、社交或大量设备指标。完整离线搜索与离线路由属于独立能力，不能因为参考 Organic Maps 就宣称已具备。

最低回归场景：

1. 地图长按保存“补水点”，退出重开，列表、地图和搜索都能找到。
2. 搜索结果收藏后，从收藏直接规划，不再重新输入坐标。
3. 改名、分组、备注和坐标更新，所有入口一致；删除可撤销。
4. 无网络仍可管理收藏；在线搜索失败不影响本地地点。
5. 快速修改两次目的地，较慢的旧结果不会覆盖最后选择。
6. 添加途经点后按真实道路规划；一段失败时不允许开始残缺导航。
7. 保存两条路线，重启后均可打开；回放与真实骑行入口清楚分开。
8. 无码表可规划并手机导航；连接码表后两端当前路线与版本一致。
9. 覆盖安装迁移有旧标签的实际数据；模拟一次事务失败后可以重试且不重复。
10. 大字体、小屏、横竖屏切换、键盘打开均没有重要按钮被挡。

## 9. 本轮原型的边界

交互原型演示四入口、地点详情、收藏新增/编辑/分组/检索/删除撤销、GeoJSON 导入导出、路线保存与途经点编辑、骑行页面和设备状态。

原型收藏与路线保存在浏览器本地，与已安装 Android App 的数据分离。背景道路来自此前已获取的 OpenStreetMap 数据；地点、路线方案、蓝牙状态、骑行数字均为明确标注的示例。原型不访问 GPS、蓝牙或在线规划，不是新版安装包。
